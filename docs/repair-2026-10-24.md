# CRS refresh repair — 2026-10-24

## Incident evidence, not a green-badge workaround

The six-hour inventory captured at 2026-10-24 07:08 UTC contained seven failed production/monitor runs: six executions of `CRS refresh watchdog` and one `CRS official-current reconciliation`. The repeated failures were chiefly one unresolved R49491 original, not seven different missing-report incidents.

The official detail API for R49491 advertised only HTML while `currentVersion` was **2**. `task_from_item` used `next(...)` without a default, assuming every detail had a PDF format. This raised `StopIteration`; its empty string became an empty diagnostic. Re-running the same parser could not repair the condition.

A separate public-original check successfully retrieved:

`https://www.congress.gov/crs_external_products/R/PDF/R49491/R49491.2.pdf`

The file is 859,877 bytes, 24 pages, SHA-256 `8daccd774bd61ce8a6f362dbfa77d1e22a98c86903e4d5dc77e0af8f0c21753d`. Its cover identifies R49491 and the expected title; the final page identifies `R49491 · VERSION 2 · NEW`. This is direct content evidence, not acceptance of the old mirror v1 or an API list-version number. The advertised HTML URL returned 403; no access controls were bypassed.

Diagnostic runs: `40072950534` (snapshot/run inventory), `40073056968` (advertised HTML), `40073227685` (independent official v2 PDF and revision check).

## Changes

* Official format parsing validates response shape and supports PDF/HTML labels and MIME labels. Empty formats and bad responses produce explicit error types and messages.
* If the detail API omits PDF, a PDF candidate is derived only from its **currentVersion** and an official HTML namespace. It is accepted only after independently downloading the official file and matching the embedded report ID, revision and cover title. List-level `version` is never used to guess a current PDF. An old mirror cannot satisfy current-version coverage.
* An explicitly advertised HTML original is supported when no verified current PDF is available. Exact raw HTML is preserved separately with SHA-256 and a Markdown derivative in `data/html-original-manifest.json`. HTML is never renamed to PDF or added to PDF counts. Denial pages and wrong-report content are rejected.
* The collector retains non-PDF/current-format discoveries for official reconciliation. Official current-format failures stay pending; the successful watermark never advances over a missing/corrupt/unverified original.
* Independent verification re-resolves changed live update signals before checking actual original bytes. Timestamp drift alone is not proof of missing content. A newly served file with different bytes still fails until it is really archived. A UTC date rollover alone does not invalidate recent evidence.
* Production handoffs use explicit `workflow_dispatch`: collection → official reconciliation → independent verification → health review. Reconciliation failure routes to monitoring rather than launching a guaranteed-to-fail downstream audit. This avoids recursive `workflow_run` recovery chains and uses active-run deduplication.
* The watchdog remains hourly. A successful monitoring run that detects an unhealthy archive writes **unhealthy** to `data/health.json` and maintains one deduplicated incident Issue; it no longer emits another failed Action every hour for the same incident. Failure to read, execute, notify or persist monitoring evidence still fails the watchdog task. Production errors remain real failures.
* The watchdog reads the latest verification result, not only the last successful receipt. Failed attempt timestamps are not labelled last-successful refresh times. The two-hour startup grace applies only to age warnings, never to confirmed missing or corrupt originals.

No existing original is deleted; no repository secret or account/ACL permission is modified. Existing twice-daily refresh schedule, rolling lookback/catch-up, current-version reconciliation, and independent external monitoring remain in effect.

## Acceptance conditions

Local and deployed regression suites must pass. Then run actual collection, official-current reconciliation, independent live-byte verification and watchdog. Acceptance requires zero official pending entries and empty missing/unverified/invalid-files arrays; R49491 v2 must exist in the manifest with the independently observed SHA-256 above. Use actual source/verification receipt timestamps, not commits or watchdog `checked_at`.

Past failed Actions remain historical records. No claim is made that external services can never fail; the repair removes the demonstrated parser/trigger/notification defects while preserving truthful error reporting for real failures.
