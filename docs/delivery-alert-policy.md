# 每日交付与降噪告警规则（2026-10-28）

## 完整性不打折，通知按影响分级

采集、官方当前原文对账、独立原文核验继续保留各自真实结果。GitHub Actions 的绿色仅表示该阶段正常执行并保存了可信证据；内容是否完整仍须读取 status.json、official-status.json、verification-status.json。不得把部分成功写成内容完整，也不得用 Git 提交或看门狗 checked_at 充当源站刷新。

1. 单份可恢复下载失败、暂时不可用的辅助 HTML、旧镜像异常：记录 warning、保留原始重试任务、继续下游官方对账和独立核验，不让相同问题反复制造失败邮件。
2. 实际归档损坏、当前任务凭据缺失或过期、代码/执行/持久化失败：仍应失败，不能用 continue-on-error 掩盖。
3. 超过26小时无成功刷新或独立核验、必需内容问题持续超过26小时、工作流被禁用或长时间卡住：通过现有单一告警 Issue 集中升级，避免同一故障多阶段重复通知。外部独立监控仍需检查平台停跑。
4. 按北京时间完整自然日统计新增原文，在次日08:00以后检查。整日没有任何新增报告时只发一次交付提醒。可选历史补抓不算新增交付；源站确实没有新报告并不等于刷新失败，提示必须区分这两种情形。

## R45635 类故障的通用修复

近期更新信号不能把所有旧镜像都提升为当前必备原文。只有同时满足以下证据，旧镜像任务才转入历史补抓队列：原出版日期早于所有曾请求的存档窗口；刚刚解析的官方当前任务具有更新出版日期；该官方文件已保存；官方来源 URL、报告编号、日期、实际文件 SHA-256 与存档记录一致。原旧任务的 URL 和校验值完整保留，不伪称补抓已完成，不放松失败 PDF 的校验。

真正仍是当前版本的旧封面日期报告、日期未知的报告，以及曾属于请求窗口的历史漏抓，均不能用此规则降级。
